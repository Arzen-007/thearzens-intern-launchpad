# THE ARZENS — Ship Your Project Free

## Input list for verification

The new resource scan will cover eight delivery routes: static websites and portfolios; frontend web apps; backend APIs and worker processes; full-stack applications; managed databases and file storage; free virtual machines and container servers; domains, subdomains, DNS, and TLS; and browser-based AI or agent workspaces.

## Intern decision journeys

| What the intern needs to ship | Start with | Required warning |
| --- | --- | --- |
| Portfolio, documentation, landing page | Static hosting | A free host is not the same as a free custom domain. |
| React, Next.js, Vue, or client-side app | Frontend platform | Check build minutes, bandwidth, and framework support. |
| REST API, webhook, bot, or small service | Serverless/PaaS runtime | Check sleep behavior, request limits, and outbound-network policy. |
| App with auth, data, and API | Frontend plus database/backend stack | Keep secrets server-side; free quotas have hard limits. |
| Docker service or CTF scoreboard | VM or container-capable host | Do not run intentionally vulnerable services on public internet without isolation. |
| Student project with a custom address | Free subdomain or student-domain benefit | Ownership, renewal, and country eligibility must be verified. |
| Project assistance and automation | AI workbench or agent | Free access, browser tools, and code execution differ by product. |

## Selection rules

Each record needs an official primary URL, a plain-language free access type, account/card expectations, region or Pakistan note, best-fit project, and one operational warning. The interface will guide interns toward a recommended starter stack rather than imply that a single platform is best for every task.
